# 振り返り 2026-09-13 — 旧文字列ドット絵の撤去（Sprint S）で見つかった 2 つの潜伏不具合

対象: DEBT-003（旧文字列ドット絵の削除）を「自走できる部分」として進めた半日。削除の前に使用状況を計測したことで、公開版に残っていた不具合 2 件（BUG-023・BUG-024）が見つかった。

## うまくいったこと

| 事項 | なぜ効いたか |
|------|-------------|
| 削除の前に「何が実行時に描かれているか」を機械的に測った（manifest と文字列定義の突き合わせ、全 8 面の地形文字列と `DECO_MAP` の重なり、`assets.pickups.*.hd` の実値） | 「全部生成素材に置き換わっているはず」を確認したら、落ちたアイテムだけが旧絵のまま公開されていた（BUG-023）。思い込みで削除していたら気づかなかった |
| golden（画素ハッシュ）が 8 面の 90 フレーム目の差を検出した | 原因を推測せず、旧コードと新コードの同一フレームを描いて差分の bbox（331,486〜427,504）を出し、足元のほうきだと特定できた。推測（「落ちたアイテムだろう」）は外れていた |
| 不採用の生成物も台帳と raw に残した | ほうき v1（171×36）を数値で不採用にでき、v2 の判断根拠になった |
| ユーザーの評価を実測付きで記録した | 「部品の合成で生きた動きではない」に、2 コマの差 46%・全幅に散る、という測定を添えたので次の生成指示（穂先だけ動かす）に変換できる |

## 失敗と学び（重要度順）

### 1. フォールバックが不具合を隠していた
- 事象: 素材が読めないときに旧文字列ドット絵で補う設計だったため、(a) 全素材が読めない BUG-014 が「粗い絵で動く」ように見えた、(b) `pickups` が生成素材の合流前に作られていて落ちたアイテムだけ旧絵だった（BUG-023）。どちらも例外もログも出ない
- 原因: 「無いより何か描ける方がよい」という設計が、欠落を見えなくした
- 学び: **欠落は目立つ形で見せる**（manifest 寸法の市松プレースホルダ＋ `ASSET.FAIL`。ADR-0040）。参照表（`pickups` のような合成テーブル）は**元データを全部そろえた後に作る**

### 2. NaN 座標は静かに何も描かない
- 事象: `assets.broom` に `w`/`h` が無く `centerX - w/2` が NaN になり、二段ジャンプのほうきは公開版で一度も描かれていなかった（BUG-024）。`drawImage` は NaN で例外を出さない
- 原因: スプライトの形（`{r,l,w,h}`）を型やテストで固定していなかった
- 学び: **描画に渡すスプライトは全部同じ形にする**（loader が `w,h,hd` を必ず付ける。プレースホルダも同形）。「画面に出ているはずのもの」は golden の画廊のように**必ず描くテストに入れる**（ほうきは通常プレイ 20 秒の 90 フレーム目に出ていたので golden が拾った）

### 3. 差分の原因を推測で書きかけた
- 事象: golden の差を「落ちたアイテムの絵が変わったから」と説明しかけた。実際はほうきだった
- 学び: **ハッシュが変わったら、同じフレームを新旧で描いて画素の bbox を出す**。説明は bbox の中身から書く

### 4. 細長い小物の生成でモデルは幅の指示を守らない
- 事象: 「キャンバス幅の 40%」「2 本横並び」と書いても 78% 幅で描き、2 本は縦に積んだ（pitch 5 px、各 159×38）
- 学び: 大きさはプロンプトで縮めず、**後処理で同一列を削る**（`shorten_to`）か、**部位指定**（穂先だけ上下 2〜3 セル、柄と結び目は同一）で 2 コマの差を制御する。IMP-029 へ

### 5. セッション再開で dev server と scratchpad が消えた
- 事象: 途中で `nohup` の Vite が死に、検証スクリプトも消えていた
- 学び: 検証スクリプトはリポ内の `tools/` か `test-results/` に置くか、都度作り直せる小ささにする。HANDOFF に起こし直しコマンドを書いておくのは有効だった

## 午後の追記（ほうき生成・BUG-006・デプロイ）

### 6. 基準に収まらないとき「緩める」を先に提案した
- 事象: 私服の白い布の陰影色が 15 色に収まらず、肌影色を共有して薄桃のスカートにした。ユーザーに「色数の制約は表現力より重要か」と問われた
- 原因: 元絵の 12 色を不変と決めつけ、実機のパレット差し替え（衣装ごとにパレット全体を設計し直す）を考えなかった
- 学び: **基準の中で設計し直す案を先に出す**（髪の階調を 1 段畳んで 1 枝空ける）。緩める案は代替として数値付きで並べ、ユーザーが選ぶ。結果は 15 色のまま解決（ADR-0041 追記）

### 7. 色 → 色の置換で「規則置換の限界」に当たった
- 事象: 髪の陰影とスカートの襞、前髪のハイライトと衣装、襟のクリームと目の白、が同じ色。色だけでは分けられない
- 学び: **画素の位置分類**（確定色を種にした BFS、連結成分の隣接数）で分ける。閾値は推測せず、成分ごとの隣接数を表にして決める（目の白 0〜1・襟 4〜43・星 2）。試行 9 回はすべて画素数を測って次を決めた

### 8. 別プロジェクトの dev server に確認を当てた
- 事象: セッション再開後、5173 が別プロジェクト（ALCHEMION）に取られていた。`curl` が 200 を返したのでカタログ確認を進め、「8 ページ error 0」を証跡にした
- 学び: ポートが空いていることと、本プロジェクトが配られていることは別。**確認前に配信物の目印（`src/catalog/index.js`）を curl で見る**。CLAUDE.md に追加

### 9. 記録スクリプトが落ちてコードだけコミットした
- 事象: docs を書き換える python が SyntaxError で 1 行も実行されず、直後の `git commit` はコード・素材だけを含んだ（別コミットで補った）
- 学び: **コミット前に `git diff --stat docs`** で記録が入っているか見る。CLAUDE.md に追加

### 10. 生成モデルは細長い小物の大きさ指示を守らない
- 事象: ほうき v1 単体 171×36、v2「2 本横並び・幅 40%」でも各 159×38（縦に積んだ）
- 学び: 大きさは後処理（同一列の削除 `shorten_to`）で揃える。`docs/gen-pipeline.md` §1.1 に追記済み
