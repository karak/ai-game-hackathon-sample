# 生成パイプライン仕様（Gemini 2.5 Flash Image → 論理ピクセル PNG）

## 1. 出力仕様（プロンプトで Gemini に強制する契約）

| 項目 | 値 |
|------|----|
| キャンバス | 1024×1024 px（モデル固定） |
| 論理グリッド | **1 セル = 8×8 px**（= 論理 1 画素）。キャンバスは 128×128 セル。実測でモデルは 8〜9px セルを最も安定して守る（16px 指定は無視されがち） |
| セル規則 | 1 セルは単色。セル未満の細部・アンチエイリアス・グラデーション禁止。セル境界は 8 の倍数座標に揃える |
| スプライト箱 | 論理 W×H セル以内（主人公 48×64、雑魚 64×68、ボス 64×96〜104×120）。ゲーム内部解像度 512×448 で 1 セル = 1 画面画素 |
| `specs.json` の `box`（論理箱） | `[W, H]` セル。3 箇所で同じ値を使う: ①`gemini_gen.py` が prompt の「Logical box」に書き、絵はこの箱に収めて高さの 85% 以上を使わせる（上限であり目標でもある）②`build_sprites.py` が後処理 `postprocess.py --logical WxH` の論理キャンバスにする ③manifest の `fits`（箱に収まったか）の QA 基準。検査専用ではないので `max` とは呼ばない（DEBT-007）。部位ごとの寸法は `part_sizes` が別に持つ |
| 配置 | 箱をキャンバス中央、足元はキャンバス下端から 4 セル上のベースライン（y=960px） |
| 複数フレーム | 1 リクエスト最大 2 フレーム。フレーム間は緑の空白 ≥ 4 セル |
| 背景 | 純緑 #00FF00 のみ。影・床・枠・文字なし |
| 色数 | キャラ 12〜15 色。輪郭は暗紫/暗茶 1 セル（純黒禁止） |

プロンプト本文は `assets/gen/prompts/_style.txt`（スタイル契約）＋ 各素材の記述で構成する。
挿絵級（カットイン・エンディング等の一枚絵）は specs の `style: "_illust_style.txt"` で契約を差し替え、`style_refs` に **画風の尊重物（`assets/sprites/ending/scene1.png` or `scene6.png`）＋キャラ立ち絵ベース（`assets/gen/ref/lyrica-illust*.png`）** を置いて毎回添付する（IMP-022、`docs/art-standard.md` §1.3・§2.6）。生成後は `tools/style_check.py` で尊重物と並べて測る。縦長の参照で出力が縦長になるときは正方形の切り抜き参照に替える。明るい場面で輪郭が明るいときは `outline_val_max: 0.23`（最暗 1 色だけ暗くする）。

## 1.1 実測で分かったモデルの挙動（2026-09-08）

- 「1 セル = N px」の言語指示やチェッカーテンプレートは**守られない**。モデルは自前の密度（1 セル ≈ 4〜6 px、キャンバス一杯で約 100〜200 セル）で描き、格子は数 px 単位で歪む。
- 単体キャラ 1 リクエストはキャンバスを埋めるため約 100 セル高になる。**2 フレーム横並び**にすると各フレーム約 100 セル高で安定する（これを基準密度とした）。
- 要素の大小はプロンプトでは制御しにくいので、**ゲーム側の解像度を密度に合わせる**（768×672）判断をした。
- 「首なし」など極端な欠損はモデルが拒む傾向（頭を描き足す）。帽子などの付属物はフレーム間で脱落することがある → 後処理で色抽出して合成する。

## 2. 後処理 I/F（`tools/postprocess.py`）

```
postprocess.py RAW.png OUT.png --logical WxH [--cell 16] [--palette BASE.png] [--anchor bottom|center]
postprocess.py RAW.png OUTDIR/ --logical WxH --split --names a,b [--palette BASE.png]
```

処理順（縮小フィルタは一切使わない）:
1. **クロマキー**: 四隅から背景色を推定し、距離 < tol または緑優勢の画素を透明化（`--nokey` で全面絵の空を除外）
2. **セル境界検出**: 色変化量を列方向・行方向に投影し、その極大位置をセル境界候補とする。候補間隔の中央値をピッチとし、規則格子を候補へスナップ（±40%）して歪んだ格子に追従する
3. **セル抽出**: 各セルの内側 50% 領域の最頻色を 1 画素にする（透明が過半なら透明）。落ち影の帯は除去
4. **分割**: 透明列でフレームを分け、幅 8 セル未満のゴミは捨てる。単体指定で複数体描かれた場合は最初の 1 体
5. **量子化**: `--palette` 指定時はその PNG の色へ最近傍写像。未指定時は MEDIANCUT で `--colors` 色（キャラ 15、地形 24、背景 32）
6. **出力**: 自然サイズの透過 PNG ＋ 同名 `.json`（`w,h,colors,fits,pitch`）。`fits` は specs.json の最大箱との照合結果

## 3. 生成台帳

`tools/gemini_gen.py` が `tools/gen_ledger.json` に全リクエストを記録する（セッション予算 200）。
生成 raw は `assets/gen/raw/`、プロンプトは `assets/gen/prompts/`、後処理済みは `assets/sprites/`。

## 4. 受入基準

- 後処理後の論理サイズが specs.json の最大箱に収まる（`fits: true`）。収まらない raw は不採用（`use` でバージョン固定可）
- 色数がカテゴリ上限以内、キャラは 10 色以上（`test/art-standard.test.js` が manifest を検査）
- 画面密度: スプライト・中景装飾は 1 セル = 1 画面画素。背景は空 3・遠景 3・中景 2 画面 px/セル（1 リクエストの横幅制約による妥協、`src/gfx/hdworld.js` の `BG_PX`）
- カタログ（`catalog.html`）でゲーム倍率（3×）表示し、参照画像と並置して確認
