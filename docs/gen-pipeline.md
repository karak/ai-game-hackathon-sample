# 生成パイプライン仕様（Gemini 2.5 Flash Image → 論理ピクセル PNG）

## 1. 出力仕様（プロンプトで Gemini に強制する契約）

| 項目 | 値 |
|------|----|
| キャンバス | 1024×1024 px（モデル固定） |
| 論理グリッド | **1 セル = 8×8 px**（= 論理 1 画素）。キャンバスは 128×128 セル。実測でモデルは 8〜9px セルを最も安定して守る（16px 指定は無視されがち） |
| セル規則 | 1 セルは単色。セル未満の細部・アンチエイリアス・グラデーション禁止。セル境界は 8 の倍数座標に揃える |
| スプライト箱 | 論理 W×H セル以内（主人公 48×64、雑魚 64×68、ボス 64×96〜104×120）。ゲーム内部解像度 512×448 で 1 セル = 1 画面画素 |
| 配置 | 箱をキャンバス中央、足元はキャンバス下端から 4 セル上のベースライン（y=960px） |
| 複数フレーム | 1 リクエスト最大 2 フレーム。フレーム間は緑の空白 ≥ 4 セル |
| 背景 | 純緑 #00FF00 のみ。影・床・枠・文字なし |
| 色数 | キャラ 12〜15 色。輪郭は暗紫/暗茶 1 セル（純黒禁止） |

プロンプト本文は `assets/gen/prompts/_style.txt`（スタイル契約）＋ 各素材の記述で構成する。

## 2. 後処理 I/F（`tools/postprocess.py`）

```
postprocess.py RAW.png OUT.png --logical WxH [--cell 16] [--palette BASE.png] [--anchor bottom|center]
postprocess.py RAW.png OUTDIR/ --logical WxH --split --names a,b [--palette BASE.png]
```

処理順:
1. **クロマキー**: 四隅から背景色を推定し、距離 < tol または緑優勢の画素を透明化
2. **グリッド推定**: 色境界の x/y 位置の周期性から実セル幅 `step` と `offset` を推定（既定 8、許容 6〜40）。契約値と異なっても実測値を使う（縮小はしない）
3. **セル多数決ダウンサンプル**: 各セルの中心 60% 領域の最頻色を取る（透明が過半なら透明）
4. **配置**: 論理 W×H の箱に anchor（既定: 足元下揃え・水平中央）で貼る。はみ出す場合は `step` を再推定して縮小
5. **量子化**: `--palette` 指定時はその PNG の色（≤15）へ最近傍で写像（同一キャラのフレーム間でパレットを共有＝衣装スワップを index 置換で行う）。未指定時は MEDIANCUT で 15 色
6. **出力**: 論理サイズの透過 PNG ＋ 同名 `.json`（`logical`, `step`, `offset`, `colors`, `source`）

## 3. 生成台帳

`tools/gemini_gen.py` が `tools/gen_ledger.json` に全リクエストを記録する（セッション予算 200）。
生成 raw は `assets/gen/raw/`、プロンプトは `assets/gen/prompts/`、後処理済みは `assets/sprites/`。

## 4. 受入基準

- 後処理後の PNG が論理サイズ通りで、色数 ≤ 15、透明率が箱の 30〜80%
- グリッド推定 `step` が 7〜10 の範囲。外れた場合は論理サイズが仕様から外れるので再生成
- 後処理後の論理サイズが specs.json の箱に収まる（`fits: true`）。収まらない raw は不採用
- カタログ（`catalog.html`）でゲーム倍率（3×）表示し、参照画像と並置して確認
