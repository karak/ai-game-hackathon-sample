# Retro Game Art Direction

## Overview

絵の良し悪しは主観語で語らない。**基準（数値＋出典＋参照画像）を先に文書化し、報告は「基準に対する測定値・テスト結果・スクリーンショット」で行う。**
寸法や解像度は記憶で決めず、実機の実寸表と参照画像の計測から導き、承認を取ってから素材を作る。

**Violating the letter of these rules is violating their spirit.** 「今回は明らかに良い」も主観である。

## When to Use

- 「〜風のクオリティで」と言われた（聖剣伝説 2、クロノ・トリガー、ロマサガ 3 など固有名の指定）
- スプライト寸法・内部解像度・色数を決めようとしている
- 作った絵について進捗報告を書こうとしている
- デザインカタログ／キャラクターシート／ステージ資料を作る

## The Rules

1. **基準文書が先**: `docs/art-standard.md` に、参照（URL・出典）→ 計測値 → 数値基準（解像度、キャラ寸法、色数、輪郭色、陰影段階、頭身、背景層数、フォント）→ 判定手順、の順で書き、承認を得てから制作する。
2. **数値には出典**: 「16×24 はロマサガ 3 フィールド相当、聖剣 2 は約 24×32、クロノは 16×35、超魔界村アーサー 28×32」のように**実寸の根拠**を添える。出典が言えない数値は使わない。
3. **参照を計測してから使う**: 参照画像は「何の基準（寸法／頭身／陰影／色数）として使うか」を 1 行で確認し、論理ピクセル数・色数・輪郭の性質を測って記録する。ズームして格子を目視する。
4. **解像度は素材の実測密度から**: 生成・描画した主人公の論理高さが画面高の 14〜16% になるように内部解像度を選ぶ。決めた後に計測ミスが分かったら**即撤回して再提案**する。
5. **報告の形（必須の 4 要素）**: (a) 基準項目ごとの測定値（寸法・色数・コマ数）、(b) テスト結果、(c) スクリーンショットの場所、(d) 未達項目と次の手。これ以外の評価語（「いい感じ」「統一されている」「視認性を確認済み」「完成状態」）は書かない。
6. **カタログは資料として作る**: 章立て = キャラクターシート（同一基準線のサイズ比較、衣装×モーション、コマの tick、当たり判定・アンカー重ね、パレット）／敵・ボス（HP・行動・弾・演出の表）／アイテム・弾（パラメータ表）／タイル（ID 付き、隣接ルールの配置例、装飾の接地点）／背景レイヤー（層ごとの寸法・px/セル・スクロール係数・繰り返し幅、合成）／ステージ（俯瞰マップに記号、区間表、難度曲線、要所の実描画）／UI（寸法表と実描画）。「並べただけ」は資料ではない。
7. **手描きの限界を早く認める**: ピクセル文字列の手描きが 2 回連続で基準未達なら、画像生成＋後処理へ切り替える（generating-pixel-art-with-gemini）。3 回目の描き直しはしない。

## Rationalization Table

| 言いたくなること | 現実 |
|------------------|------|
| 「敵が一目瞭然なので OK」 | 判定基準は視認性だけではない。寸法・色数・陰影段階・頭身を測って比べる |
| 「1995 年風に統一できた」 | 統一の定義（パレット・輪郭色・密度）を数値で示せないなら主張しない |
| 「16×16・6 色で装飾は十分」 | それはファミコン水準。SNES スクウェアの雑魚は 24〜48、15 色。出典を見る |
| 「参照はクォータービューだが密度の参考にはなる」 | 用途が違う参照は測っても基準にならない。まず何の基準か確認 |
| 「カタログに全部並べたから資料になっている」 | 数値・当たり判定・tick・スクロール係数が重なっていなければ、絵の一覧にすぎない |
| 「承認済みの解像度なので変えない」 | 承認の根拠（計測）が誤りなら、承認ごと撤回して再提案する |
| 「もう一度描き直せば届く」 | 2 回未達なら手段を変える |

## Red Flags — STOP

- 報告文に「いい感じ」「良好」「統一」「確認済み」「完成」が入っている
- 寸法・色数を出典なしで書いた
- 参照画像をズームせずに数値を出した
- 基準文書がないまま素材を 3 点以上作った
- カタログの章が「キャラ」「敵」「背景」の並べ替えだけ

**いずれも、基準文書と計測に戻る。**

## Standard Template

`docs/art-standard.md` の最小構成:

```
1. 参照（URL、用途、計測値）
2. 数値基準: 解像度 / タイル / 主人公・雑魚・ボス・小物の寸法レンジ / 色数 / 輪郭 / 陰影段階 / 頭身 / 背景層 / フォント・UI
3. 判定手順: 自動テスト（manifest 検査）→ カタログ並置 → シーン合成 → 証跡付き報告
```
