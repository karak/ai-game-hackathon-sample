# Gemini 2.5 Flash Image のドット絵生成: 実測された挙動（2026-09）

81 リクエスト（成功 75）の観測。数値は目安。モデル更新で変わりうるので、最初の 1 リクエストで再確認する。

## 密度・サイズ

| 構図 | 1 体の論理サイズ（セル） | セル幅（px） |
|------|------------------------|-------------|
| 単体キャラ、キャンバス 80% と指示 | 約 70〜75 × 105〜110 | 8（まれに 21） |
| 2 フレーム横並び | 約 45〜60 × 100〜110 | 5 |
| 4 体横並び（アイコン） | 約 25〜55 × 25〜55 | 5 |
| 雑魚 2 フレーム | 46〜92 × 65〜101 | 5〜9 |
| ボス単体 | 113〜163 × 140〜176 | 5〜7 |
| 背景の帯（横長 1 列） | 幅 250〜320 × 高 40〜130 | 4〜5 |
| 地形ストリップ | 幅 190〜265 × 高 100〜160 | 4〜5 |

- 「1 セル = 16px」「128×128 セルのグリッド」「16 の倍数に揃えろ」は守られない
- チェッカー柄のテンプレート画像を渡すと、モデルは自前の細かいチェッカーを描き、絵が劣化する
- 「箱の 85% を使え」は守られるが、箱の絶対サイズは守られない → **横並びの体数でサイズを制御する**
- 1 枚に 4 体以上入れると、各体が小さくなり細部が潰れる。キャラは 2 体まで、小物は 4 個まで

## 格子の性質

- セル幅は画像内で 4〜6 px の間で揺れる（非整数ピッチ、局所的な歪み）
- 境界はソフト（1〜2 px の中間色）→ 同色ランの長さは実セル幅より短く出る
- 周期推定（mod 一致率、自己相関、ランレングス最頻値）はいずれも約数・倍数・半値に誤爆した
- 有効だったのは **色変化量の列/行投影の極大を境界候補にし、中央値ピッチの規則格子を候補へスナップ**する方法。平坦部（境界なし）は規則格子で補う

## 内容の一貫性

| 指示 | 結果 |
|------|------|
| 参照画像＋「同じキャラ」 | 顔・配色・比率はよく保たれる |
| 帽子ありで走りコマ 2 枚 | 2 枚目で帽子が消えることがある（約 1/3） |
| 衣装変更（紺のセーラー服へ） | 2 回とも元の色のまま。参照が強すぎる |
| 首なし（頭を描かない） | 3 回とも頭あり。欠損表現は描き足される |
| 背景に「月・空を描くな」 | 明記しないと中景に月や地面が入る。明記すれば従う |
| 「影を描くな」 | 足元の楕円影が付くことがある → 後処理で除去 |
| 純緑 #00FF00 背景 | 実際は (120,199,118) 前後。四隅から推定してキーする。薄い格子模様が入ることもあるが緑優勢なので落ちる |

## プロンプト構成（効いた形）

```
[STYLE CONTRACT]  画風（16-bit SNES JRPG、輪郭は暗紫、12〜15 色、3〜4 段の陰影）、背景は純緑のみ
[SIZE CONTRACT]   体数・並び・足元の基準線（自動生成）
[SUBJECT]         キャラの固有情報（髪・目・服・小物）、ポーズ、向き、フレームの内容、
                  「かわいい要素 1 つ・えげつない要素 2 つ」のような意匠の指定
[REFERENCE]       参照画像の役割（同一キャラ、同一グリッド）
```

## 差分コマ（同一キャラの別ポーズ）— 2026-09-08 追記

- 参照画像＋「ATTACK frame」指定でボス 3 体の攻撃コマを 1 回ずつ生成 → 3/3 でキャラの同一性は保たれた（配色・顔・服）。幅は待機コマの 1.0〜1.35 倍（腕を上げる／涙の弧が伸びる）
- **単体指定でも付属物（浮遊するハート・飛沫）は別成分になる**。後処理が「最初の成分」を取ると 11×25 のハートだけが切り出された → 単体は「不透明画素が最多の成分」を採用（`postprocess.py`）
- 2 コマの差を出すには「羽の上下」だけでは弱い。**腕の位置・体の高さ（セル数）・付属物の数**を FRAME 1 / FRAME 2 で別々に書くと 2 枚が明確に変わる（キノコ妖精 v2: 83×94 と 84×113）
- 「浮遊物は体から 6 セル以内」と書くとフレーム分割が安定する

## 背景層の落とし穴 — 2026-09-08 追記（第三章 涙の川）

- 題材に「川」「水面」を含む中景・遠景は、**水面を地面として描く**（キーが効かず矩形の水面が残る）。中景・遠景の SUBJECT には題材の水を書かず「岸の物体だけ」を列挙し、STRICT KEY 文（「物体の背後・間・下は純緑のみ。水・地面・霧・枠・パネルを描かない」）を必ず付ける。5 枚中 5 枚で再生成になった
- 「This is VARIANT A」と書くと **画像内に "VARIANT A" の文字を描く**ことがある。配置の違いは「Arrangement A: 柳 2 本、橋の柱 1 本…」のように物体の内訳で指示し、末尾に「no text, no labels, no captions」を置く
- `keep_bottom` は **内容 bbox に切り詰めた後の比率**で切る（`extract_cells` が先に bbox 化する）。空を含まない層に付けると柳の上半分が落ちる（103 → 52 セル）。空・月が混ざった層にだけ使う
- 地形帯の上部にキーが残ることがある（緑が (98,106,107) に量子化されて一様な灰色帯になった）。`TILE_BANDS` は行ごとの平均色を計測して決める

## 失敗の内訳（69 中 6）

- 格子・サイズ契約の再試行: 4（守られない指示を繰り返した）
- 衣装変更: 2（後処理で解決すべきだった）
- 欠損表現: 別表現に変更して吸収

## 後処理パラメータの既定

- クロマキー: 背景推定色との L1 距離 < 60、または g>140 && g>r+50 && g>b+50
- セル抽出: 内側 50% 領域の最頻色（16 段階量子化で集計）。透明が過半なら透明
- 量子化: キャラ 15 色、小物 12、地形 24、背景 32（MEDIANCUT、ディザなし）
- 影除去: 最下 4 行のうち、3 行上より 25% 以上幅広く、60% 以上が暗い行
- フレーム分割: 8 近傍連結成分、bbox が 2 セル以内なら併合、幅 8 未満は捨てる。期待数に足りなければ占有最小列で割る
